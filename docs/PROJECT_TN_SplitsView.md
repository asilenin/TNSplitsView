# TN Splits View + garmin-raw MCP — Project Reference

Справочник проекта для использования в новых чатах. Описывает: (1) приложение
TN Splits View (Garmin Connect IQ data field), (2) MCP-коннектор `garmin-raw`
для чтения тренировок, (3) критичные технические решения, которые легко
сломать, если не знать предысторию.

---

## 1. Что это за проект

**TN Splits View** — Connect IQ data field для бега (Forerunner 955 / 965 / 970,
экран 454×454, touch). Делает две вещи:

1. **Список кругов (laps)** с цветовой кодировкой по темпу: номер, время,
   дистанция, темп. Текущий незавершённый круг показывается «живой» строкой
   снизу, обновляется каждую секунду, отделён линией.
2. **Логирование лактата** прямо на часах во время бега (по тапу), запись
   в FIT-активность developer-полем. Значение лактата пользователь получает
   сам внешним прибором — приложение только записывает число.

**garmin-raw** — отдельный MCP-коннектор (Python), читает тренировки из Garmin
Connect, включая лактатное поле, записанное приложением.

## 2. Приложение: ключевые технические решения

Эти решения дались методом проб и ошибок. Менять их без понимания причины —
значит наступить на те же грабли.

### 2.1. Ввод — только onTap
На часах data field принимает **только** `onTap`. `onSwipe / onHold /
onNextPage / onKey / onSelect` — мертвы на FR965 (проверено: счётчики всех
семи BehaviorDelegate-событий остались 0). Реализация: полноценный
`WatchUi.DataField` + отдельный `BehaviorDelegate`, возвращаемые парой из
`getInitialView()` → `[view, delegate]`. `onTap(evt).getCoordinates()` даёт
координаты. Работает **только на железе**, не в симуляторе (Activity Data
в симуляторе серое).

### 2.2. Эмодзи
💧 и 🔁 рендерятся на FR965 в стандартных шрифтах, **только** как реальные
UTF-8 символы в исходнике (НЕ как `\U`-escape — компилятор отвергает).
Крупный шрифт `FONT_NUMBER_MILD` НЕ содержит эмодзи-глифа → в MAX-карточке
вместо капли пишется текст `LA:`.

### 2.3. Запись лактата в FIT — САМОЕ ХРУПКОЕ МЕСТО
FitContributor **record-поле** сохраняет последнее значение в КАЖДУЮ
последующую секундную FIT-запись, пока не задать новое. Наивная запись
«только в момент подтверждения» → значение размазывается на всю тренировку.

**Рабочая схема (буфер):**
- переменная `_pending` на старте = 0;
- тап OK кладёт значение (целое ×10, напр. 60 = 6.0) в `_pending`;
- `compute` каждую секунду пишет `_fieldRecord.setData(_pending / 10.0)`;
- если `_pending != 0` — обнуляет `_pending` сразу после записи.

Результат: чистая точка в секунду замера, 0.0 в остальное время. Два
одинаковых замера = две разные точки (буфер обнуляется между ними).

Что НЕ работает: `setData(null)` между точками **роняет приложение**
(иконка Garmin IQ). Запись значения напрямую в `confirmLactate` (вне `compute`)
— гонка с `compute`, теряется. Только буфер через `compute`.

### 2.4. appID developer-поля
- Поле: `developerFieldNumber = 1`, единицы `mmol/L`.
- **При sideload appID нулевой** (`00000000-...`) — это документированное
  поведение Garmin (STORE_ID из нулей вместо настоящего appID).
- **После публикации в Store** appID станет настоящим:
  `7c294f6c-58ec-4064-bcfe-342189d548f0` (из манифеста).
- Имя поля в FIT теряется — Garmin переименовывает в
  `connectIQDeveloperField-NN`, цеплять по имени нельзя.
- Чужое поле Stryd: appID `18fb2cf0-1a4b-430d-ad66-988c847421f4`,
  field numbers 0/8/9/10 — не пересекается с нашим field 1.

### 2.5. fitContributions
Чтобы лактат рисовался графиком в Garmin Connect — нужен блок
`resources/fit/fit.xml` с `<fitField id="1" ... chartTitle dataLabel
unitLabel fillColor>`. Без него поле пишется, но не отображается графиком.

### 2.6. Размеры и единицы
- Все координаты — доли от `_w`/`_h` (`dc.getWidth()/getHeight()`), не
  пиксели → масштабируется на разные экраны.
- Шрифты — системные абстракции (`FONT_TINY/SMALL/MEDIUM/...`), не pt →
  система сама масштабирует под устройство.
- Дистанция/темп ХРАНЯТСЯ канонически (метры, сек/км); ОТОБРАЖАЮТСЯ в
  системных единицах часов (`System.getDeviceSettings().paceUnits`).

### 2.7. Три режима списка
- MIN — 8 строк, левое выравнивание.
- MID — карусель 5 строк (TINY/SMALL/MEDIUM/SMALL/TINY), центр активный,
  по центру, БЕЗ номера в центральной строке. Линия над живым треком.
- MAX — карточка: номер (мелко) / время / дистанция / темп.
- Режим выбирается настройкой `listMode`; в режиме All центр-тап циклирует
  MIN→MID→MAX.

## 3. Настройки приложения (properties / settings)

| ключ | тип | значения / дефолт |
|---|---|---|
| `listMode` | number | 0=All(tap), 1=MIN, 2=MID, 3=MAX |
| `lactateEnabled` | boolean | false |
| `thresholdUnit` | number | 0=km, 1=mile (единицы ВВОДА порогов) |
| `pace1..pace6` | string | mm:ss, дефолты 4:00/4:30/5:00/5:30/6:00/7:00 |
| `color1..color7` | number | индекс палитры |

**Палитра цветов** (индекс): 0=белый, 1=голубой, 2=зелёный, 3=жёлтый,
4=оранжевый, 5=красный, 6=фиолетовый. Дефолты color1..7 = 6,5,4,3,2,1,0
(фиолетовый→белый).

**Пороги темпа:** 6 редактируемых верхних границ → 7 цветовых зон (7-я = ∞).
Вводятся в формате `mm:ss`. Пользователь меняет только «до» каждой зоны;
«от» = предыдущее «до» + 1 сек; первое «от» = 0; последнее «до» = ∞.
Покрытие без дыр гарантировано по построению.

**Парсинг mm:ss:** в коде (НЕ в экране настроек — там нет валидации формата).
Проверка: есть двоеточие, минуты 0–59, секунды 0–59, непусто. При ошибке —
экран `Settings error / Threshold N invalid: "xxx" / Use mm:ss (e.g. 4:30)`
вместо краша. Внутри всё конвертируется в канон сек/км.

**Старт лактата:** константа 2.0 (диапазон LT1/LT2 = 2–4 ммоль/л).

## 4. MCP-коннектор garmin-raw

Python MCP-сервер, читает Garmin Connect. Репозиторий: `Garmin-TN-MCP`
(garmin_raw/: auth.py, backend.py, server.py, export.py, install.py).

### 4.1. Инструменты (tools)

| tool | назначение |
|---|---|
| `list_activities(start_date, end_date, sport="running")` | список тренировок за период |
| `get_activity_laps(activity_id)` | круги: время/дист/темп/ЧСС по кругам |
| `get_activity_streams(activity_id)` | посекундные потоки (для длинных >12км может превысить 1 МБ) |
| `get_activity_comment(activity_id)` | текстовая заметка активности |
| `get_activity_lactate(activity_id)` | **лактатные точки из нашего developer-поля** |
| `get_wellness(date)` | восстановление/сон/HRV за день |
| `get_personal_records()` | личные рекорды |

### 4.2. Чтение лактата — как работает get_activity_lactate

Логика (backend.py), КОРРЕКТНАЯ, не менять без причины:

```python
_LACTATE_DEV_FIELD = 1
_LACTATE_APPIDS = {
    "00000000-0000-0000-0000-000000000000",  # sideload
    "7c294f6c-58ec-4064-bcfe-342189d548f0",  # после публикации
}
_STRYD_APPID = "18fb2cf0-1a4b-430d-ad66-988c847421f4"

# поле ищется по developerFieldNumber == 1, НЕ Stryd,
# appID в наборе наших ИЛИ None (sideload отдаёт None/нули)
if (m["developerFieldNumber"] == _LACTATE_DEV_FIELD
        and appid != _STRYD_APPID
        and (appid in _LACTATE_APPIDS or appid is None)):
    lact_idx = m["metricsIndex"]
```

Отметка = любой сэмпл со значением **> 0**; нули = «нет замера». Каждая
точка привязывается к ближайшему кругу по таймстампу.

Ответ:
```json
{"activity_id": 23396020167, "count": 2,
 "points": [
   {"timestamp_ms": 1782563165000.0, "mmol": 2.0, "distance_m": null, "lap": 6},
   {"timestamp_ms": 1782563174000.0, "mmol": 3.0, "distance_m": null, "lap": 8}
 ]}
```
`count: 0` БЕЗ ключа `error` = поле найдено, но все значения ≤ 0 (нет замеров).
`count: 0` С `error` = поле не найдено в активности.

### 4.3. Выгрузка в JSON (CLI)

```bash
# из папки проекта коннектора, через uv:
uv run garmin-raw-export --start 2026-06-27 --end 2026-06-27 \
    --activity 23393721989 --streams --out today.json
```
Структура: `{period, sport, activities:[{summary, laps, comment, streams}]}`.
`--streams` добавляет посекундные потоки (metricDescriptors + activityDetailMetrics).
Авторизация — `uv run garmin-raw-auth` (если ещё не авторизован).

Прямой curl к Garmin без сессии возвращает 404/HTML — использовать только CLI
коннектора или MCP-ручки.

### 4.4. Как читать наше поле в сыром JSON
1. в `streams.metricDescriptors` найти запись с `developerFieldNumber == 1`,
   appID нулевой (sideload) или `7c294f6c-...` (после публикации), НЕ Stryd;
2. взять её `metricsIndex`;
3. в `streams.activityDetailMetrics` пройти строки, собрать те, где значение
   по этому индексу **> 0** — это отметки лактата с таймстампами
   (`directTimestamp`).

## 5. Окружение / факты

- Целевые устройства: FR955, FR965, FR970 (экран 454×454, touch, идентичны).
- SDK: connectiq-sdk-mac 9.2.0. Контейнер компилировать не может —
  синтаксис проверяется вручную, сборка у пользователя в VS Code.
- App version при публикации: 1.0.0. appID манифеста:
  `7c294f6c-58ec-4064-bcfe-342189d548f0`. Permission: только FitContributor.
- Публикация: apps.garmin.com/en-US/developer/upload. Обычная (не «for testing»,
  иначе требует другой appID). Hero image 1440×720 (GIF/PNG/JPG, ≤2048 КБ).
  Скриншоты, описание с tap-сценарием, категория Running.
- DSA-верификация разработчика (apps.garmin.com/dsa) — иначе региональные
  ограничения.
- После публикации appID в FIT станет настоящим → коннектор цепляет поле
  по `7c294f6c-...` однозначно.
